# DOGGYWOOD MODERATION SPECIFICATION

## 1. Purpose

Doggywood publishes user generated dog videos and public reviews.

Moderation is a version one requirement.

No contest entry should become publicly discoverable before moderation approval.

## 2. Submission checks

Moderator should be able to verify:

Video is playable.

Video duration is valid.

Video is substantially vertical.

Dog or pet is visibly relevant to the video.

Written review exists.

Review does not contain obvious private account information.

Video does not contain obvious dangerous or abusive treatment.

Video does not contain prohibited explicit content.

Video does not clearly violate another person's privacy.

User has accepted content rights terms.

## 5. Moderator workflow

Open pending entry.

View video.

Read caption.

Read Verify.Dog review.

View dog profile.

View customer eligibility status.

Select decision.

Select reason.

Add optional internal note.

Submit.

Action creates audit event.

## 6. Public reports

Authenticated users can report a published entry.

Report categories:

Animal Safety

Harassment

Explicit Content

Privacy

Copyright

Spam

Fraud

Other

Reports create a moderation review record.

A report does not automatically remove the video.

## 7. Emergency removal

Administrator can immediately hide a published entry.

The system records:

Who removed it.

When.

Why.

Whether contest score was affected.

Whether votes were invalidated.

## 8. Review privacy

Review text should be scanned for obvious information that should not be public, including:

Phone number

Email address

Home address

Account number

Medical document identifiers

Moderator can reject or request resubmission if sensitive information appears.

## 9. Audio and music

Contest terms should require the entrant to own or have permission for submitted audio.

The moderation interface should include a Copyright Concern reason.

Version one should avoid supplying a licensed commercial music catalog unless a separate licensing solution is implemented.

## 10. Minor safety

Version one account registration should be designed for adults.

If a minor visibly appears in user content, the terms should require the submitting adult to have authority to publish that content.

Administrative escalation should be available for uncertain cases.

## 11. Moderator privacy

Moderators should see only eligibility evidence required for their role.

Sensitive customer verification evidence should not be exposed publicly.

Administrative access should be role controlled and audited.
